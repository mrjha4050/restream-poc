## Running the Application

```bash
npm install                      # Install dependencies
cp .env.example .env             # Create .env file, fill in Google OAuth credentials
node index.js                    # Start server on http://localhost:3000
```

No build step, no tests, no linter configured.

### Environment Variables

Required for YouTube OAuth:
- `GOOGLE_CLIENT_ID` — OAuth app client ID from Google Cloud Console
- `GOOGLE_CLIENT_SECRET` — OAuth app client secret
- `GOOGLE_REDIRECT_URI` — OAuth redirect URL (default: `http://localhost:3000/auth/youtube/callback`)
- `SESSION_SECRET` — Session encryption key (default: `change-me-in-production`, must be changed for production)

Optional:
- `AWS_REGION` — AWS region for IVS (default: `us-east-1`)

## Architecture

**Restream** is a Node.js/Express app that receives a live stream from AWS IVS and rebroadcasts it to multiple platforms (YouTube, Twitch, Facebook, or custom RTMP) simultaneously using FFmpeg.

### Backend (`index.js`)

Single-file Express server (port 3000) with these responsibilities:

- **Stream lifecycle** — `startFFmpeg()` spawns FFmpeg with codec-copy (no re-encoding) from the IVS input URL to one or more RTMP outputs. Implements auto-restart with exponential backoff (up to 3s delay); restart counter resets if the stream runs >60 seconds.
- **State object** — tracks `running`, `pid`, `uptime`, `restartCount`, and a circular log buffer (max 200 entries).
- **Real-time logs** — FFmpeg stderr is captured and pushed to all connected SSE clients (`GET /stream-logs`) and stored in the log buffer.

REST API:
| Method | Path | Purpose |
|--------|------|---------|
| GET | `/platforms` | List supported platforms + their RTMP base URLs |
| POST | `/platforms/:id/start` | Start stream to platform (`ivsUrl`, `key`, optional `autoRestart`, `maxRestarts`) |
| POST | `/platforms/:id/stop` | Stop stream to platform |
| POST | `/stop` | Stop all active streams |
| GET | `/status` | Current state + stats for all platforms |
| GET | `/logs` | Historical log buffer (JSON) |
| GET | `/stream-logs` | SSE endpoint for live FFmpeg output |
| GET | `/auth/youtube` | Redirect to Google OAuth consent screen |
| GET | `/auth/youtube/callback` | OAuth redirect handler (exchange code for tokens) |
| GET | `/auth/youtube/status` | Check if YouTube is authenticated + return user email |
| POST | `/auth/youtube/fetch-key` | Fetch stream key from YouTube API + auto-start stream |
| POST | `/auth/youtube/disconnect` | Clear YouTube OAuth session |
| POST | `/overlay` | Send timed metadata to IVS channel |

Platform RTMP endpoints are hardcoded in `index.js` lines ~18–22 (`PLATFORMS` object).

### Frontend (`public/`)

Single-page vanilla JS app:
- **`app.js`** — fetches `/platforms` to render platform cards dynamically, handles start/stop form, polls `/status` every 3s for stats, connects to `/stream-logs` via `EventSource` for live logs. Includes a client-side uptime timer and log filtering (all / connections / connections+disconnections).
- **`index.html`** — three-section layout: stream config inputs, live stats, log viewer.
- **`style.css`** — dark-themed responsive UI using CSS custom properties.

### YouTube OAuth Integration

**YouTube platform** uses OAuth instead of manual key entry:
1. User clicks "Connect with YouTube" button on YouTube card
2. App redirects to Google OAuth consent screen
3. User authorizes → app receives access token (stored in `req.session.youtubeTokens`)
4. User enters IVS URL and clicks "Start Stream"
5. App fetches stream key from YouTube Data API (`liveStreams.list`)
6. FFmpeg auto-starts streaming to YouTube

**One-time setup** (user must do):
1. Go to [Google Cloud Console](https://console.cloud.google.com)
2. Enable "YouTube Data API v3"
3. Create OAuth 2.0 Web Application credentials
4. Add redirect URI: `http://localhost:3000/auth/youtube/callback`
5. Copy `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` into `.env`

### Key Constraints

- FFmpeg must be installed and available on `PATH`.
- YouTube tokens are stored in server-side sessions (in-memory, lost on restart) — users must re-authorize after server restart.
- Twitch, Facebook, Custom platforms still require manual stream key entry.
- Stream keys are held only in browser memory; they are never persisted server-side.
- All state (logs, restart counts, YouTube tokens) is in-memory and lost on server restart.
